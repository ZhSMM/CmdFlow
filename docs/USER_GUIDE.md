## 基本概念

CmdFlow 有 4 个核心概念：

| 概念 | 含义 | 类比 |
|---|---|---|
| **命令 (Command)** | 一个可执行的单元（带参数） | 函数 |
| **工作流 (Workflow)** | 由多个节点组成的有向无环图 | 流水线 |
| **节点 (Node)** | 工作流中的一个步骤 | 函数调用 |
| **执行 (Execution)** | 一次工作流或命令的实际运行 | 一次函数调用 |

数据流：上游节点的 `output` → 下游节点可通过 `{{nodeId.field}}` 引用。

## 命令库

### 创建命令

1. 进入「命令库」页面
2. 点「新建命令」
3. 填写：
   - **名称**：在命令库中显示的名字，如 `git push`
   - **类型**：执行环境（cmd / pwsh / python / node / bash）
   - **模板**：实际执行的命令，用 `{{name}}` 引用参数
   - **工作目录**：可选，命令执行时所在目录
   - **超时**：可选，超过时间会强制 kill
4. 添加参数：
   - **变量名**：模板中引用的名字
   - **显示名**：UI 上显示的标签
   - **类型**：12 种之一
   - **默认值 / 必填 / 敏感**

### 参数类型

| 类型 | 用途 | UI |
|---|---|---|
| `text` | 单行文本 | 输入框 |
| `textarea` | 多行文本 | 多行输入框 |
| `number` | 数字 | 数字输入框 |
| `boolean` | 布尔 | 开关 |
| `select` | 下拉单选 | 下拉框 |
| `multiselect` | 多选 | 复选框列表 |
| `file` | 文件路径 | 文件选择器 |
| `dir` | 目录路径 | 目录选择器 |
| `password` | 密码（加密） | 密码输入框 |
| `json` | JSON 数据 | JSON 编辑器 |
| `datetime` | 日期时间 | 日期时间选择器 |
| `cron` | Cron 表达式 | 文本输入框 |

### 模板示例

```bash
# Git push
git push origin {{branch}} --force

# Docker
docker run -d -p {{port}}:{{port}} --name {{name}} {{image}}

# 带条件
{% if clean %}rm -rf ./dist && {% endif %}npm run build
```

注：当前版本只支持 `{{var}}` 简单变量替换，条件语法属于 Phase 5+。

## 工作流

### 创建工作流

1. 进入「工作流」页面
2. 点「新建工作流」
3. 进入画布

### 添加节点

从左侧面板拖拽节点到画布。

### 连接节点

鼠标 hover 到节点右边的圆点（handle），拖拽到目标节点的左边圆点。

### 编辑节点

点击节点 → 右侧属性面板自动渲染该类型的配置表单。

### 编辑边

点击边 → 右侧显示触发条件：
- **上游成功时**（默认）
- **上游失败时**
- **总是**

### 验证 DAG

点工具栏「验证」→ 后端检查：
- 是否有环
- 是否有孤立节点
- 节点类型是否合法
- 参数引用是否合法

### 保存

点「保存」→ 写入 SQLite。

### 运行

点「运行」→ 后端拓扑排序后并行执行。

## 执行

### 单命令执行

1. 进入「执行」页面
2. 上方下拉框选择命令
3. 左侧自动出现参数表单
4. 点「预览」查看渲染后的最终命令
5. 点「执行」

### 工作流执行

1. 在「工作流」页面点 ▶ 按钮
2. 或在画布里点「运行」

### 实时输出

右侧 xterm 终端实时滚动 stdout（白色）/ stderr（红色）/ system（黄色）。

### 取消

点「取消」按钮可中断执行（tokio CancellationToken 传播到所有运行中节点）。

## 调度

### 创建调度

1. 进入「调度」页面
2. 点「新建调度」
3. 选工作流 + 写 Cron 表达式 + 选模式
4. 点「创建」

### Cron 表达式

5 段标准格式：`分 时 日 月 周`

| 表达式 | 含义 |
|---|---|
| `0 2 * * *` | 每天凌晨 2 点 |
| `*/5 * * * *` | 每 5 分钟 |
| `0 9 * * 1-5` | 工作日 9 点 |
| `0 0 * * 0` | 每周日零点 |

### 调度模式

- **应用内**：应用启动时扫描，应用关闭则不触发
- **OS 计划任务**：注册为 Windows Task Scheduler / macOS launchd / Linux systemd
- **混合**：应用内优先，OS 兜底

### 立即触发

调度列表右侧 ▶ 按钮，不等下次触发时间立即跑。

## 历史与回放

### 查看历史

进入「历史」页面：
- 按状态筛选（成功/失败/运行中）
- 自动刷新（5s）
- 显示触发方式（手动/调度）

### 查看详情

点击某条记录 → 弹窗显示：
- 输入参数
- 每个节点的 stdout / stderr / 输出数据 / 错误

### 重放

点「重放」按钮 → 用相同参数重新执行（生成新 execution_id）。

## 安全机制

### 三层防护

1. **黑名单**：内置 8 条规则拦截危险命令（`rm -rf /`、`format c:` 等）
2. **危险启发式**：检测 `rm / del / drop / git push --force` 等操作
3. **命令预览**：执行前显示最终命令

### 处理流程

- 命令命中黑名单 → 阻断，要求显式 override
- 命令含危险操作 → 弹窗确认
- 两者都没有 → 直接执行

### 敏感字段

- 类型为 `password` 的参数值用 OS keyring 加密
- 不写日志、不持久化到执行历史
- 运行时解密后注入到子进程

## 高级技巧

### 工作流参数

工作流级别参数可在所有节点中用 `{{name}}` 引用。

### 数据传递

节点 A 输出 `{ "result": "ok", "count": 42 }`，
节点 B 模板：`{{A.result}} - {{A.count}}`。

### 错误处理

- 边条件 `on_failure`：上游失败时执行
- 边条件 `always`：无论成败都执行
- 一个节点失败，工作流状态变 failed，但已启动的下游（on_failure / always）继续

### 性能

- 同层节点并行执行（默认 4 并发）
- 大输出用 xterm 虚拟滚动

### 数据库位置

SQLite 数据库存放在 `app_data_dir/cmdflow.db`：
- Windows: `%APPDATA%\dev.cmdflow.app\cmdflow.db`

## 常见问题

**Q: 命令执行没反应？**
A: 检查模板语法（{{name}} 大括号不要少），检查参数是否必填且没填。

**Q: DAG 一直显示有环？**
A: 节点 A → B → A 是环。画布编辑器会自动检测，提示哪些节点在环里。

**Q: 调度没有触发？**
A: 检查调度是否启用、工作流是否启用、next_run_at 是否已到。

**Q: AI 节点报错？**
A: 现阶段用环境变量 `OPENAI_API_KEY` 注入 key。Phase 4 已预留 keyring 接口，Phase 5 完善 UI。
